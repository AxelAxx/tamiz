## Decisions (flagged for Alex's review)

- **The policy gains a required `privacy` section (version 3).** It holds:
  - an action per level (`allow`, `anonymize`, `restrict_to_local`, `block`), with
    optional residencies;
  - `localRoute`;
  - `onDetectorError`: `restrict_to_local` or `block`; `allow` is not accepted.

  Boot rejects `critical: allow` unless its residencies are limited to `local` and
  `eu`.
- **Default policy (R-11):**

  | Level | Action |
  |---|---|
  | `none`, `low` | `allow` |
  | `high` | `anonymize`, limited to `[local, eu]` |
  | `critical` | `restrict_to_local` |
  | detector failure | `restrict_to_local` |

- **The gateway anonymizes from `/analyze` results instead of calling `/anonymize`
  (R-01).** This keeps the detection cache free of values and numbers placeholders across
  messages. The placeholder rule exists in Python and TypeScript, held equal by shared
  vectors.
- **`block` → `451 policy_blocked`, not the backlog's `422` (R-05).** A detector failure
  with `block` → `503 privacy_unavailable`, a new error type.
- **`decide()` returns `route | block` (R-04).** An empty chain after privacy filtering
  becomes `block` (`no_target`).
- **One detection call per request over the joined messages (R-02).** A finding that
  crosses a message boundary is treated as a contract failure (fail closed).
- **Detection cache (R-08):** SHA-256 key, in memory, LRU with TTL. It holds positions
  only, and failures are not cached. There is no Valkey adapter, deliberately.
- **Versioned placeholder notice** (`prompts/anonymization-notice.v1.md`, R-06), added
  only for `anonymize` and reported in `x-tamiz-privacy: anonymize;notice=v1`.
- **New headers** `x-tamiz-sensitivity` and `x-tamiz-privacy`, plus
  `POST /v1/simulate`, which returns entities, decision, chain and, for `anonymize`, the
  provider-bound messages.
- **The leak metric is defined for feature 007 (R-12).** A leak is a labelled value in
  clear going to a target outside its level's raw-allowed residencies.
- **Honest risk: the < 2 % name-leak threshold may fail with the default policy.** PERSON
  recall is 0.917 on corpus v1, and a missed name in an otherwise clean request is routed
  as `none`. The spec says so; feature 007 measures and decides.
- **Interim state.** Between `T-005-02` and `T-005-04`, the decision receives a
  `NOT_INSPECTED` constant (`none`), so `main` keeps 003 behaviour until inspection is
  wired. It is removed in T036.
