## What was done

With `DATABASE_URL` set, the gateway stores the audit log and API keys in PostgreSQL.

**Schema and migrations.** The schema is Drizzle (`audit_entries` with a column per
filterable field and no content column; `api_keys` with hash, role and revocation). The
migration `drizzle/0000_init.sql` is generated by drizzle-kit and committed. It runs at
boot before the server listens; a failure exits with the error code only.

**The asynchronous writer.** It implements the audit port:
- `append` only queues;
- batches of 100 are written every 250 ms through the clock port;
- a failed batch is retried once, then dropped;
- a full queue (10 000) drops the oldest entry;
- every loss is an `audit.dropped` routing event plus a `warn` line;
- `close` flushes on `SIGTERM`.

**API keys.** Keys have a role: `client` (`TAMIZ_API_KEYS`) or `admin`
(`TAMIZ_ADMIN_API_KEYS`, new). `createAuthenticator` checks the environment keys first
(constant time), then the database by hash; a revoked key is refused. The middleware now
also sets `role`, for `T-006-04`'s admin-only routes.

**Configuration and tooling.**
- `TAMIZ_AUDIT_HASH_KEY` is required with `DATABASE_URL`.
- Scripts `db:generate`, `db:migrate` and `api-key:add <client> [--admin]`.
- The compose `postgres:17` service.

## Decisions

- **No application `ApiKeyRepositoryPort`.** Authentication is not a use case: it is
  composed in `main.ts` as an `Authenticate` function. The repository is consumed through
  the structural `StoredKeyLookup` type. Adding a port would be ceremony (constitution X).
- **`Authenticate` may be async and returns a principal** (`clientId`, `role`). The two
  test call sites were updated.
- **`onConflictDoNothing` on insert.** A retried batch that partly succeeded must not
  fail on the duplicate id and drop the rest.
- **Costs are stored as `numeric(14,8)`.** `fromRow` converts them back to numbers, and
  the round trip equals the domain entry exactly (Testcontainers test).
- **`api_keys.role` is plain text in SQL**, with no `CHECK`. Drizzle's enum typing and the
  insert paths constrain it; a `CHECK` can come with the next migration if wanted.
- **Migrations at boot**, and `db:migrate` for operators (R-04).

  credentials; log `error.code`.

  migrations miss the change.
