# Implementation Plan: Provider Routing

**Branch**: `002-provider-routing` | **Date**: 2026-10-18 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-provider-routing/spec.md`

## Summary

Deliver the routing half of Tamiz on top of the feature 001 skeleton: a pure domain
(`ModelTarget`, `RoutingPolicy`, rule-based `classify()` and a total, deterministic
`decide()` returning an ordered chain), application ports (`LlmProviderPort`,
`PolicyRepositoryPort`) and use cases (`classifyTask`, `routeInference`), four AI SDK 6
adapters (Ollama via `@ai-sdk/openai-compatible`, Mistral, Anthropic, OpenAI) with
retries disabled and errors normalised into `ProviderError`, a YAML policy file validated
by a `RoutingPolicySchema` in `@tamiz/contracts` and loaded at boot, the
OpenAI-compatible `POST /v1/chat/completions` on `@hono/zod-openapi` with SHA-256-hashed
API keys, `x-tamiz-route` / `x-tamiz-rule` headers and a generated `/openapi.json`, cost
per request in `Usd` returned as `usage.cost_usd`, and a synthetic routing dataset
(`routing.v1.jsonl`) with a Vitest gate at ≥ 95 % expected-route accuracy. Only the
first target of the chain is executed here; feature 003 executes the rest.

## Technical Context

**Language/Version**: TypeScript 5.x strict (001 flags), ESM, Node.js 22 LTS.

**Primary Dependencies**: feature 001 set (Hono 4, Zod 4, pino, Vitest) plus
`@hono/zod-openapi` (OpenAPI from Zod 4, `OpenAPIHono`, `createRoute`),
`hono/body-limit` (built in), `ai` 6 + `@ai-sdk/openai-compatible` (Ollama) +
`@ai-sdk/mistral` + `@ai-sdk/anthropic` + `@ai-sdk/openai`, `yaml` 2 (policy file),
`node:crypto` (SHA-256, `timingSafeEqual`, `randomBytes`); dev: `msw` 2 (provider
tests), `fast-check` (property tests).

**Storage**: N/A. Policy in memory (seeded from a file), API key hashes in the
environment. Feature 006 adds PostgreSQL.

**Testing**: Vitest (001 root `projects`); in-process HTTP with `app.request()`; MSW
`setupServer` for the four adapters; `fast-check` for `decide()`; dataset gate test
reading `packages/evals/datasets/routing.v1.jsonl`; one child-process boot test extended
for invalid policy / missing provider settings.

**Target Platform**: Linux containers, GitHub Actions `ubuntu-latest`; developed on
Windows 11 (Git Bash + PowerShell).

**Project Type**: monorepo (one web service + libraries), unchanged.

**Performance Goals**: classify + decide < 5 ms p95; endpoint overhead with a fake
provider < 20 ms p95 (SC-007); local-only quickstart in < 10 min (SC-009).

**Constraints**: domain and application import nothing from workspace packages or
libraries (001 rules; R-01 explains the consequence); no prompt content, keys or
upstream bodies in logs or error bodies (SC-005); AI SDK retries off (R-04); invalid
policy, key configuration or missing provider settings stop boot before the port is
bound (SC-006); the chain is not executed beyond `chain[0]`.

**Scale/Scope**: 4 providers, 1 endpoint + OpenAPI, 1 policy schema, 6 task types ×
3 sizes, ~15 new domain/application modules, 4 adapters, 1 dataset (≥ 40 cases).
Backlog tasks `T-002-02` … `T-002-08`.

domain and contract, with a drift test for closed lists, R-03). It is not a constitution

**Post-design re-check (after Phase 1)**: unchanged. The design added no package and no
port beyond the two above; the `ProviderRegistry` is an application-level type built in
`main.ts`, not a port (it has one implementation and no I/O).
